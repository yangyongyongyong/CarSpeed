# 测速雷达预警逻辑

## 运行边界

测速雷达预警是独立能力，不属于行车录像设置，也不依赖是否正在录像。

- 入口：`RadarAlertSettingsActivity`
- 后台服务：`RadarAlertService`
- 高德巡航与播报控制：`RadarAlertController`
- 纯规则计算：`RadarAlertPlanner`

`RadarAlertService` 是 `foregroundServiceType="location"` 的前台服务。开启后即使 App 退到后台，也会通过前台通知保持运行，并用 GPS 更新当前速度。

## 语音开关

语音控制复用 `VoicePhotoRecognizer` 的离线 Vosk 命令识别。雷达预警支持两个独立短语：

- `测速雷达开`：写入 `radar_alert_enabled=true`，并启动 `RadarAlertService`。
- `测速雷达关`：写入 `radar_alert_enabled=false`，并停止 `RadarAlertService`。

语音命令必须是完整独立短语，归一化后要求整句等于命令文本。

- `测速雷达开` 会触发。
- `测 速 雷 达 开` 会触发。
- `请测速雷达开` 不触发。
- `测速雷达开一下` 不触发。
- `前方测速雷达开拍` 不触发。

开启命令需要已有精确定位权限；如果权限缺失，只语音提示需要权限，不会把雷达开关写成开启。

## 到达时间计算

高德回调提供测速摄像头距离，App 使用当前最新 GPS 速度估算到达时间：

```text
etaSeconds = cameraDistanceMeters / (currentSpeedKmh / 3.6)
```

规则：

- 只使用当前速度，不使用平均速度。
- 速度低于 `5km/h` 时不计算 ETA，也不触发语音，避免停车或低速抖动误报。
- 默认提醒阈值是 `20秒、10秒、5秒`。
- 默认语音提前量是 `2秒`，即 `eta <= threshold + leadSeconds` 时进入该阈值提醒窗口。

## 多摄像头锁定

同一路段可能同时返回多个测速摄像头。为避免第一个摄像头 5 秒提醒时，第二个摄像头 20 秒提醒也插进来，当前实现有“当前摄像头锁定”机制。

规则：

- 每次只锁定一个当前摄像头，初始选择距离最近的测速摄像头。
- 当前摄像头未判定通过前，后续摄像头即使已经进入 20 秒/10 秒/5 秒提醒窗口，也不允许播报。
- 如果当前摄像头仍在高德回调列表中，持续只处理这个摄像头。
- 如果当前摄像头短暂从回调列表消失，但尚未进入通过区间，则继续保持锁定，不让第二个摄像头接管。
- 如果当前摄像头已经进入通过区间，并且从回调中消失至少 `8秒`，认为已通过，允许切换到下一个摄像头。
- 如果当前摄像头长期丢失超过 `30秒`，认为路线/高德数据变化，释放锁定，避免永久卡住。
- 如果当前摄像头进入通过区间后，距离从历史最近距离反向增加超过 `40米`，也认为已通过。

通过区间不是固定米数，而是和当前速度有关：

```text
passZoneMeters = max(30m, currentSpeedMps * (最小提醒阈值 + 语音提前量 + 1秒))
```

默认 `5秒` 阈值、提前 `2秒` 时，约等于“最后一次 5 秒提醒窗口附近”。这样高速行驶时，即使摄像头在几十米外被高德回调移除，也能正确释放锁定。

## 阈值去重

每个摄像头按 key 记录已经播报过的阈值。

如果第一次看到某摄像头时已经很近，例如 ETA 只有 5 秒，那么 20 秒和 10 秒窗口都已经错过。此时只播报最接近当前 ETA 的 `5秒`，并同时把 `20秒、10秒、5秒` 标记为已处理，避免之后倒序补报旧阈值。

## 数据状态提醒

测速雷达数据依赖高德智能巡航回调。手机联网不等于一定会立刻收到雷达回调；如果当前路段没有回调、SDK 还没返回点位、或服务刚启动，App 只能知道“暂未收到高德回调”，不能判断为“下载失败”。

触发条件：

- 只有车辆移动时才提醒。当前速度低于 `5km/h` 时不提醒，避免停车场景反复播报。
- 如果系统网络不可用，语音提示：`网络不可用，测速雷达数据可能无法更新，请注意观察路况`。
- 如果网络可用，但高德测速雷达回调超过 `60秒` 没有更新，只记录状态 `高德暂未回调测速雷达数据`，不再语音播报。
- 同类数据异常提醒有 `180秒` 冷却时间，避免弱网环境下频繁打扰驾驶。

数据更新时间的定义：

- 只要 `onUpdateAimlessModeElecCameraInfo` 有回调，无论本次是否包含测速摄像头，都认为高德测速数据通道仍然活跃。
- 如果没有任何测速回调，才进入“数据暂未更新”的判断。

数据状态不会关闭雷达服务。后续高德回调恢复后，正常摄像头预警会继续工作。

## 离线数据与方向限制

当前实现使用 `AMapNavi.startAimlessMode(AimLessMode.CAMERA_DETECTED)` 获取高德智能巡航摄像头回调。高德地图离线包可以用于地图底图/回放显示，但当前 SDK 回调没有提供可由 App 主动下载和离线查询的测速雷达数据库。

`AMapNaviTrafficFacilityInfo` 在当前 SDK 版本只暴露：

```text
longitude / latitude / type / distance / limitSpeed
```

没有摄像头拍摄方向、道路方向、道路哪一侧等字段。因此 App 无法根据原始数据精确过滤“对向车道摄像头”。当前只能依赖高德智能巡航本身是否按当前行驶方向返回点位；如果高德回调把对向点也返回，App 只能做距离/锁定等弱过滤，不能可靠判断拍摄方向。

## 摄像头 key

摄像头 key 来自高德回调数据：

```text
longitude * 100000 : latitude * 100000 : cameraType : speedLimit
```

这样可以把同一个摄像头在多次回调中的状态归并起来，同时区分同位置不同类型或限速的点位。

## 测试覆盖

相关测试在 `RadarAlertPlannerTest`：

- 最近摄像头锁定。
- 第一个摄像头未通过时，第二个摄像头不接管。
- 第一个摄像头通过后，第二个摄像头才允许提醒。
- 近距离首次出现时，过期阈值不会倒序补报。
- ETA 使用当前速度计算。
- 网络不可用或测速数据长时间未更新时会提醒，且提醒有冷却时间。
- 只有网络不可用会语音提醒；高德暂未回调只记录状态，不语音打扰。
