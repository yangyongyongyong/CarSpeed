# 测速雷达预警逻辑

## 运行边界

测速雷达预警是独立能力，不属于行车录像设置，也不依赖是否正在录像。

- 入口：`RadarAlertSettingsActivity`
- 后台服务：`RadarAlertService`
- 高德巡航与播报控制：`RadarAlertController`
- 纯规则计算：`RadarAlertPlanner`

`RadarAlertService` 是 `foregroundServiceType="location"` 的前台服务。开启后即使 App 退到后台，也会通过前台通知保持运行，并用 GPS 更新当前速度。

## 语音开关

语音控制复用 `VoicePhotoRecognizer` 的离线 Vosk 命令识别。雷达预警支持两个独立短语：

- `测速雷达开`：写入 `radar_alert_enabled=true`，并启动 `RadarAlertService`。
- `测速雷达关`：写入 `radar_alert_enabled=false`，并停止 `RadarAlertService`。

语音命令必须是完整独立短语，归一化后要求整句等于命令文本。

- `测速雷达开` 会触发。
- `测 速 雷 达 开` 会触发。
- `请测速雷达开` 不触发。
- `测速雷达开一下` 不触发。
- `前方测速雷达开拍` 不触发。

开启命令需要已有精确定位权限；如果权限缺失，只语音提示需要权限，不会把雷达开关写成开启。

## 到达时间计算

高德回调提供测速摄像头的沿路剩余距离。到达时间优先用同一次巡航定位 `AMapNaviLocation.getSpeed()`（公里/小时）；这套速度超过 3 秒没有更新时，才退回系统 GPS 速度：

```text
etaSeconds = cameraDistanceMeters / (etaSpeedKmh / 3.6)
```

规则：

- 只使用当前速度，不使用平均速度。距离和车速来自同一套高德绑路定位，避免系统 GPS 车速和高德剩余距离各算各的。
- 速度低于 `5km/h` 时不计算 ETA，也不触发语音，避免停车或低速抖动误报。
- 默认提醒阈值是 `20秒、10秒、5秒`。
- 默认语音提前量是 `2秒`，即 `eta <= threshold + leadSeconds` 时进入该阈值提醒窗口。
- 播报里的米数按「这句话里的秒数 × 当前车速」计算，不直接念当次回调可能已经跳变的原始米数，避免出现「10 秒，80 米」。
- 同一个摄像头一旦开始跟踪，到达时间不能比真实经过的时间掉得更快，最多再松 2 秒。高德距离突然缩短时，不会刚报完 20 秒、过几秒又报 5 秒。新的距离如果和这条时间底线相符，就改用新距离。

## 多摄像头锁定

同一路段可能同时返回多个测速摄像头。为避免第一个摄像头 5 秒提醒时，第二个摄像头 20 秒提醒也插进来，当前实现有“当前摄像头锁定”机制。

规则：

- 每次只锁定一个当前摄像头，初始选择距离最近的测速摄像头。
- 当前摄像头未判定通过前，后续摄像头即使已经进入 20 秒/10 秒/5 秒提醒窗口，也不允许播报。
- 如果当前摄像头仍在高德回调列表中，持续只处理这个摄像头。
- 如果当前摄像头短暂从回调列表消失，但尚未进入通过区间，则继续保持锁定，不让第二个摄像头接管。
- 如果当前摄像头已经进入通过区间，并且从回调中消失至少 `8秒`，认为已通过，允许切换到下一个摄像头。
- 如果当前摄像头长期丢失超过 `30秒`，认为路线/高德数据变化，释放锁定，避免永久卡住。
- 如果当前摄像头进入通过区间后，距离从历史最近距离反向增加超过 `40米`，也认为已通过。
- 判定通过时播放两声媒体通道提示音，不受语音播报 `2.5秒` 最小间隔限制。
- 已通过的摄像头 key 会在本次雷达服务生命周期内忽略，避免距离反向增加后又重新锁定同一个点。

通过区间贴着电子眼，大约 2 秒车程，并限制在 30 到 60 米：

```text
passZoneMeters = clamp(currentSpeedMps * 2秒, 30m, 60m)
```

距离还在这个范围之外时，即使回调米数突然变大，也不算已经通过，提示音不会提前在电子眼前方一两百米响起。摄像头进入这个范围后消失至少 `8秒`，或距离从最近点反向增加超过 `40米`，才播放经过提示音并释放锁定。

## 阈值去重

每个摄像头按 key 记录已经播报过的阈值。

如果第一次看到某摄像头时已经很近，例如 ETA 只有 5 秒，那么 20 秒和 10 秒窗口都已经错过。此时只播报最接近当前 ETA 的 `5秒`，并同时把 `20秒、10秒、5秒` 标记为已处理，避免之后倒序补报旧阈值。

## 数据状态提醒

测速雷达数据依赖高德智能巡航回调。手机联网不等于一定会立刻收到雷达回调；如果当前路段没有回调、SDK 还没返回点位、或服务刚启动，App 只能知道“暂未收到高德回调”，不能判断为“下载失败”。

触发条件：

- 只有车辆移动时才提醒。当前速度低于 `5km/h` 时不提醒，避免停车场景反复播报。
- 如果系统网络不可用，语音提示：`网络不可用，测速雷达数据可能无法更新，请注意观察路况`。
- 如果网络可用，但高德测速雷达回调超过 `60秒` 没有更新，只记录状态 `高德暂未回调测速雷达数据`，不再语音播报。
- 同类数据异常提醒有 `180秒` 冷却时间，避免弱网环境下频繁打扰驾驶。

数据更新时间的定义：

- 只要 `onUpdateAimlessModeElecCameraInfo` 有回调，无论本次是否包含测速摄像头，都认为高德测速数据通道仍然活跃。
- 如果没有任何测速回调，才进入“数据暂未更新”的判断。

数据状态不会关闭雷达服务。后续高德回调恢复后，正常摄像头预警会继续工作。

## 离线数据与方向限制

当前实现使用 `AMapNavi.startAimlessMode(AimLessMode.CAMERA_DETECTED)` 获取高德智能巡航摄像头回调。高德地图离线包可以用于地图底图/回放显示，但当前 SDK 回调没有提供可由 App 主动下载和离线查询的测速雷达数据库。

`AMapNaviTrafficFacilityInfo` 在当前 SDK 版本只暴露：

```text
longitude / latitude / type / distance / limitSpeed
```

没有摄像头拍摄方向、道路方向、道路哪一侧等字段。因此 App 无法根据原始数据精确过滤“对向车道摄像头”。当前只能依赖高德智能巡航本身是否按当前行驶方向返回点位；如果高德回调把对向点也返回，App 只能做距离/锁定等弱过滤，不能可靠判断拍摄方向。

## 重叠道路层级

高架和地面在平面坐标上重叠时，单点 GPS 分不出车在哪一层。测速雷达服务同时采样加速度计和陀螺仪，用车头俯仰角识别匝道：

- 平路姿态连续稳定 30 秒后记为基准。加速时学习车头方向，所以不依赖手机在车上的固定姿势。
- 相对基准持续倾斜至少 8 秒，再回到基准并稳住 15 秒，才记为一次上下匝道。抬头是上到高架，低头是下到地面。
- 只支持一层高架。坡没有重新变平，不切换。刹车期间不用加速度计校正俯仰，避免把刹车当成坡度。
- 手机被拿起或角度突然大变时，清空识别结果。

上下坡识别本身有开关，在测速雷达页：`根据上下坡识别高架和隧道`，默认开启。关闭后不再根据倾角把路段改成高架、地面或隧道，重叠路段只按默认层级预警。

识别不出来时按设置里的默认层级预警，默认是最高层。用户可以改成最底层。设置项在测速雷达页：`重叠道路识别不出来时，按最高层预警`。

高德平行路回调出现高架上/高架下，且和当前预警层级不一致时，调用 `switchParallelRoad(2)` 切换高架上下。切换后的 8 秒内先不播报限速，避免把另一层的限速报出去。8 秒后如果回调仍停在原层，恢复播报，并在重叠路段的语音前加上「高架」或「地面」。之后每 20 秒最多再切换一次。没有高架平行路时，语音保持原来的测速内容。

没有陀螺仪的手机无法识别匝道，一直按默认层级预警。

下坡再变平，并且定位在进入后持续变弱（精度差或定位中断）时，记为隧道。定位恢复并稳住后，改记为桥下。字幕不会把普通路段标成桥上或桥下。

卫星数和信号强度用同一个开关，在测速雷达页：`根据 GPS 卫星数识别隧道`，默认开启。已经在地面，或下坡刚结束时，卫星颗数或信号强度基本没变，就记为地面；30 秒内从至少 6 颗掉到 3 颗及以下，或卫星回调中断，并持续约 3 秒，才改记为隧道。高架上少星保持高架。回到正常星数并稳住约 15 秒后改回地面。关掉后不再看卫星数和信号强度，仍按定位精度和中断判断隧道。上下坡识别关闭时，这条证据也不会改层级。识别出的桥上、桥下、隧道会写进视频字幕的所在位置后面。所在位置在路上写成市、区和路名，不在路上则写成村、镇或附近地名。

视频字幕开关在行车记录设置的「声音与字幕」里：`视频字幕在重叠路段显示桥上 / 桥下 / 隧道`。只有已经识别出层级，或高德提示当前有高架重叠时，才会写入「桥上」「桥下」或「隧道」。分享导出可以单独勾选是否保留这一项。

重合路段后面如果路线分开，会用分开后的走向回头修正刚才的层级。例如高架左拐、地面直行，定位跟着左拐，就把误判成地面的那段重叠改回高架。这段时间必须一直是平路；上下坡说明换过层，不改坡前的结果。分不清两条路时也不改。本机主动调用高架切换后的短时间里，高德标志跟着变，不算新的证据。开关在测速雷达页：`重合路分开后，按实际路线回头修正层级`，默认开启。当前行程里已经写上的桥上、桥下会按修正结果改写。

## 摄像头类型

只处理高德道路设施类型里的测速点：

- `4`：测速摄像头、测速雷达
- `11`：连续拍照，区间测速
- `102`：超速违章

`0` 是未知道路设施，不参与选眼。违章摄像头（`5`）和监控摄像头（`28`）也不是测速雷达。

## 摄像头 key

摄像头 key 来自高德回调数据：

```text
longitude * 100000 : latitude * 100000 : cameraType : speedLimit
```

这样可以把同一个摄像头在多次回调中的状态归并起来，同时区分同位置不同类型或限速的点位。

## 测试覆盖

相关测试在 `RadarAlertPlannerTest`：

- 最近摄像头锁定。
- 第一个摄像头未通过时，第二个摄像头不接管。
- 第一个摄像头通过后，第二个摄像头才允许提醒。
- 近距离首次出现时，过期阈值不会倒序补报。
- 匀速时，报过 20 秒后几秒内距离突然变短，不会接着报 5 秒；时间真正走到之后才报下一档。
- ETA 使用当前速度计算，并且优先用高德巡航定位速度。
- 播报米数和这句话里的秒数一致。
- 未知设施类型不会被当成测速雷达；经过提示音只在电子眼附近响起。
- 网络不可用或测速数据长时间未更新时会提醒，且提醒有冷却时间。
- 只有网络不可用会语音提醒；高德暂未回调只记录状态，不语音打扰。

道路层级相关测试：

- `VehiclePitchTrackerTest`：学习车头方向、抬头俯仰、刹车不伪装坡度、手机突然转动后重新学习。
- `RoadLayerResolverTest`：平路基准、上坡锁定高架、下坡锁定地面、下坡且定位变弱锁定隧道、短倾斜和长坡不切换、采样中断、手机移动后回到默认层级、字幕只在重叠或已识别时出现、分叉修正可以改写之前的层级。
- `RoadDivergenceCorrectorTest`：定位左拐对上高架、直行对上地面、两条路分不清不改、上下坡不改、高德匹配落到另一层时回头修正、本机主动切换不算证据、隧道不会被改成桥下、字幕只改重叠段之后的桥上桥下。
- `RoadLayerMonitorTest`：用模拟 IMU 走完一次上匝道再变平，结果为高架。
- `ShareSubtitleFormatterTest`：导出时可以单独保留或去掉桥上、桥下、隧道。
